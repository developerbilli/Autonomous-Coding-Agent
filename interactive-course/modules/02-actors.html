Meet the 5 Agents

How specialized roles turn chaotic LLMs into a disciplined engineering unit

Why does our system use five separate agents instead of asking one big AI model to "do everything"?

Think of a Hollywood movie set. You don't have the lead actor write the script, operate the boom mic, perform the stunts, and audit the legal clearances. If one person does all of that, the movie is a disaster. You have separation of concerns.

PLAIN ENGLISH

The blueprint created by the Manager. It forbids the Coder from wandering into random files.

High-level goal and step-by-step instructions for the team.

The explicit list of allowed target files. Any other file edit is flagged as scope creep.

Clear rules the code must satisfy to be deemed acceptable.

The Reviewer's independent verdict: can approve or veto the release.

List of critical security or quality objections that must be fixed before release.

Digital fingerprints of every reviewed file, guaranteeing no sneaky edits happen later.

Steering Tip for Vibe Coders

Notice that the Reviewer Agent is strictly read-only. It does not have access to a file write tool! Why? Because if a reviewer can edit code, it will quietly try to patch its own objections, bypassing the test generator and breaking the safety net. Keep your reviewers read-only!
